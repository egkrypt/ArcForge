# Third-party components and distribution boundaries

**ArcForge original backend/engine:** MIT, full text in root `LICENSE`. That license does not relicense the frontend, upstream projects, model weights or user content.

**ChroMapper**, Caeden117 and contributors: GPL-2.0-only. The browser frontend adapts jump and note-mirroring algorithms from tag 0.13.892 and is distributed under GPL-2.0-only (`frontend/LICENSE`). Complete ArcForge frontend source/build metadata and the exact original `SpawnParameterHelper.cs` and `MirrorSelection.cs` references are included in the public source release. The full Unity ChroMapper application is not embedded. The existing development workspace retains its separate upstream snapshot; the release only needs those original reference files alongside complete adapted frontend source.

**ArcViewer**, AllPoland and contributors: GPL-3.0. The separate source snapshot at tag v0.8.1-beta and its license are retained under `vendor/arcviewer`. The installed workspace also has an upstream hosted WebGL product reporting 0.8.1; it was not rebuilt from the tag and its exact corresponding build source has not been proven. Therefore the public archive omits that opaque hosted WASM/data/loader/framework. It does not claim the tag proves corresponding source for those bytes. [Viewer setup](integrations/VIEWER_SETUP.md) describes building and distributing a separate player. ArcViewer communicates with ArcForge through an iframe/map URL; its C# code is not linked into the GPL-2.0 frontend.

**InfernoSaber**, Frederic Brenner and contributors: MIT. Source v1.7.1 and license are retained under `vendor/inferno/InfernoSaber---BeatSaber-Automapper-1.7.1`. The installed upstream `fav_15` weights have fixed SHA-256 checks; they are omitted from the source archive. The TensorFlow/legacy-Keras adapter and FFmpeg decoder adaptation are identified in provenance. Uploads train a separate local ArcForge model, not those frozen upstream weights.

**YAMNet**, Google / TensorFlow authors: Apache-2.0. ArcForge's independent PyTorch execution follows the published YAMNet model architecture and log-mel preprocessing; attribution and the complete Apache license are in `engine/recognition`. The optional installer obtains unchanged official weights from `https://storage.googleapis.com/audioset/yamnet.h5`, verifies SHA-256, and stores them locally. Weights are not bundled in this source archive. [Official source and license](https://github.com/tensorflow/models/tree/master/research/audioset/yamnet).

**SongCore**, Kyle1413 and contributors: MIT. The examined source and complete license remain under `integrations/beatsaver/SongCore-master`. ArcForge independently expresses its map-hashing specification with bounded ZIP streams. See [training/import references](integrations/TRAINING_RUNTIME.md).

**Runtime dependencies:** PyTorch uses its BSD-style distribution license; TensorFlow Apache-2.0; React, Three.js and Vite MIT; FastAPI MIT; SciPy and NumPy BSD; threadpoolctl BSD-3-Clause; Pillow HPND; imageio-ffmpeg BSD-2-Clause. Installed distributions retain their own notices, including any bundled CUDA/FFmpeg terms. Runtime dependencies and FFmpeg binaries are not bundled in the source ZIP; the installer obtains pinned distributions. FFmpeg runs as a separate executable.

The research repositories listed in [PROVENANCE.md](integrations/PROVENANCE.md) were read for concepts during 1.3 without downloading their source archives or restricted trained assets. No license grant is inferred from a GitHub topic listing. No AST/Essentia or segmentation pretrained assets from those projects are bundled.

User music, maps, artwork and Unity bundles remain user content. Their rights are not changed by the source licenses. The public source archive excludes local music, imported maps, datasets, trained private models, caches and project backups. Upstream source snapshots can contain their own original template assets and short UI sound effects; those are upstream assets, not the user's uploaded songs.
